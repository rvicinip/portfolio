Proof it works

Numbers with a source.

1.1% → 80% reproducible steps

Analyzed 728 historical bug tickets (2022–2026). Built tooling that recovers reproducible steps for ~80% of them — up from 1.1% documented — at 75–85% precision against ground truth. A reproducible step is a step a human or an automated test can repeat to see the bug again.

A "fix" that was never deployed

Traced a configuration change to a file upload followed by zero deploys — proven through system monitoring, not guesses. The fix was live nowhere.

92% of an env's log = one stale session

Traced most of an environment's error log to one old browser session — an active person in another timezone, not a robot, not an intrusion. One conversation cleared 92% of the noise without touching code.

An audit that reviewed my own tickets

Ran 7 adversarial reviews — each one's job was to prove my filed bug reports wrong. All 7 held up; fixes were still applied where the reviews found weaker wording. The verification culture is the deliverable.

My AI stance

AI is a directed tool, not a magic wand. I work with Claude, Cursor, OpenCode, and DeepSeek daily to design modular test frameworks and accelerate analysis. Because I build AI systems myself, I know their failure modes — my rule is verification: check what was actually produced, not just whether the command ended green, and never file a bug I haven't confirmed isn't already fixed. An external verifier once proved my +231% backtest was survivorship bias — the correction became the project's most valuable result. A backtest is testing a strategy against past data; survivorship bias means the data only contains the winners, making results look better than they were.
